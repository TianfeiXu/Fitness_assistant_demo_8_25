# AI Fitness Log Assistant

A single-file **Streamlit** web app that turns free-form workout notes (English or Chinese) into
structured training data using an LLM, then visualizes your calorie trend, tracks per–body-part
**"training heat"** with time decay, and generates personalized AI coaching tips.

> Personal demo project showcasing practical LLM application engineering: robust structured
> parsing, lightweight domain modeling, and built-in observability.

## Features

- **Natural-language log parsing (EN/CN)** → structured JSON via OpenAI, hardened with strict JSON
  mode, a regex fallback, configurable retries, and Chinese-punctuation normalization.
- **MET-based calorie estimation**, with exercise/RPE-aware MET selection.
- **7-day calorie trend** line chart.
- **Body-part training heat** with exponential half-life decay (7 days) and "needs more / needs rest" thresholds.
- **AI coaching suggestions** generated from your profile + last-7-day summary.
- **Debug panel** (prompt / raw response / parsed JSON / exception / round-trip latency) and
  **Diagnostics** (model ping for latency).
- **Password gate** + API-key validation on startup.

## How It Works

1. User enters a workout log, e.g. `Bench press 60kg x5 x3; Running 30 minutes; RPE 8`.
2. The text is sent to the OpenAI API with a strict parser prompt; the model returns JSON items:
   `{date, exercise, body_part, weight_kg, reps, sets, minutes, rpe}`.
3. Parsing is hardened: forced JSON mode → regex JSON-block fallback → configurable retries →
   CN-punctuation cleanup (`；→;`, `，→,`, `×→x`).
4. Each item is enriched with estimated minutes, MET, calories, and training volume.
5. Workouts are appended to `data/workouts.csv`; body-part heat is updated in `data/heat.csv`,
   decaying between dates and accumulating new volume.
6. Charts render the 7-day calorie trend and current body-part heat (with low/high reference rules).
7. **Generate suggestions** sends a profile + 7-day summary to the model for 3–5 actionable tips.

### Heat model

Training stimulus decays over time with a **7-day half-life**:

```
HEAT_DECAY = exp(-ln(2) / 7)   # per-day multiplier ≈ 0.906
```

Each day every body part's heat is multiplied by `HEAT_DECAY`; new training volume is added on the
workout date. Parts below `HEAT_LOW = 1.0` are flagged **"needs more"**; above `HEAT_HIGH = 3.0`
are flagged **"needs rest"**.

### Calorie model

```
kcal = MET × 3.5 × body_weight_kg × minutes / 200
```

MET is chosen by exercise type / RPE (e.g. easy run `8.3`, hard strength `6.0`).

## Setup & Run

### Prerequisites
- Python 3.13
- An OpenAI API key

### 1. Install dependencies

Using Pipenv:
```bash
pipenv install
pipenv shell
```

Or with pip:
```bash
pip install streamlit pandas altair python-dateutil openai
```

> `slides.py` additionally needs `python-pptx` (`pip install python-pptx`).

### 2. Set environment variables

| Variable | Purpose |
|----------|---------|
| `OPENAI_API_KEY` | Your OpenAI API key |
| `FITNESS_APP_PASSWORD` | Login password for the app's password gate |

Windows PowerShell:
```powershell
$env:OPENAI_API_KEY = "sk-..."
$env:FITNESS_APP_PASSWORD = "your-strong-password"
```

macOS / Linux:
```bash
export OPENAI_API_KEY="sk-..."
export FITNESS_APP_PASSWORD="your-strong-password"
```

### 3. Run

```bash
streamlit run app7.py
```

Open the local URL Streamlit prints, log in with your password, and add a workout log.

## Data Model

**`workouts.csv`** — `date, exercise, body_part, weight_kg, reps, sets, minutes, rpe, est_met, est_kcal, volume`

**`heat.csv`** — `date, chest, back, legs, shoulders, arms, core, cardio, other`

Body parts are inferred from a built-in exercise→body-part map, with the LLM filling any gaps.

---

## Notes & Limitations

- CSV-based storage and a single user profile — great for a demo, not for multi-user / production
  (swap for a database).
- Password comparison is a plain-text check against an env var; suitable for a gated demo, not real auth.
- Calorie / volume figures are rough estimates, **not medical advice**.
- The 42 MB demo recording is intentionally excluded from the repo; host it via GitHub Releases or an external link.
